# 手机网页开局、战斗与聊天

0.2.8 的客户端和 Go 0.1.18 使用同一套对战协议，Windows、桌面网页与手机网页继续共享账号和房间。

## 开局准备

开始后服务端先确定本局地图与车型，进入 loading 状态，行动倒计时为零。客户端下载并校验本局按需资源，在逐帧准备车型动画、三种武器、派生弹药和道具素材后，等待画面实际渲染，再发送带 battle_id 的 battle_loaded。房间中支持该协议的真人全部确认后，首回合才开始完整的 35 秒，AI 同时恢复。

客户端通过 loading_barrier 能力标记加入。旧客户端仍按原流程加入，不会因不认识确认命令被永久卡住。确认可重试，重复确认不会延长回合，旧对局的确认不能解锁新局。加载超过 180 秒或有人离开时，取消本次开局，返回房间并显示原因，不发放奖励、不记录胜负。

## 战斗素材与地形

本局未使用的车型和武器不再在进入战场时一次性解码。本局使用的素材按约 4 毫秒的主线程工作预算分帧准备；单张贴图的加载时间仍取决于设备。确认开局前完成当前参与者的动画、武器、派生弹药及道具素材缓存。

地形仍使用同样的掩码、碰撞与伤害规则。小地图只重采样受爆炸影响的像素，不再为每次爆炸复制并缩放全图。文本字体检查只扫描显示的名称和聊天，不再重复序列化轨迹点。客户端继续使用服务端时钟，不通过延迟伤害显示来伪装网络流畅。

## 手机聊天

点击游戏内聊天输入区后，浏览器直接显示原生文本框、发送和关闭按钮。聊天栏跟随 visualViewport，键盘与屏幕旋转后重新定位。中文组字期间 Enter 不触发发送；服务器确认成功后才清空，失败显示提示并保留草稿，可再次发送。点空白处或关闭收起键盘，恢复游戏操作。桌面客户端保持原有 Enter 聊天流程。

## 验证范围

Go 加载阶段、重复与过期确认、旧端混用、超时取消及回合恢复由服务端测试覆盖。导出后的 WebAssembly 使用静音 Chromium 触控事件验证，包含双玩家、中文聊天、失败重试及可视窗口尺寸变化。渲染专项比较更新前后小地图像素，并检查当前武器在开局准备后不新增纹理解码。

这些检查不等于实体手机的帧率与输入法兼容性保证。Android 与 iOS 真机、不同浏览器和弱网仍有性能差异；原生移动发行版不包含在本次交付内。自动化记录见 validation/mobile-performance-0.2.8.json。
