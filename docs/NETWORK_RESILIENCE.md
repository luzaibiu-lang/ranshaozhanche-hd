# 网络与开局反馈

0.2.9 使用 Go 0.1.19 和同一套 Windows／Web 客户端逻辑。

## 可见的操作反馈

开始按钮在第一次点击时立即禁用，并按阶段显示准备资源、请求开局、加载战场。请求期间同步锁定准备、车型、地图及 AI 设置，防止界面显示可操作但请求被忽略。服务器拒绝或资源失败后恢复操作，加载成功后转入战场；下一局重新恢复原始开始按钮。

## 连接与同步

游戏先手动登录，再以第一帧令牌认证建立 WebSocket；令牌不进入 URL 或日志。服务端按变化推送状态，定期心跳。相同战斗中已经确认缓存的弹道使用引用，不改变轨迹、伤害、动画和特效。新连接必须先取得完整弹道。各连接只在认证玩家的状态中处理自己的操作。网络发送不持有全局游戏锁；写入超时、收包上限及队列上限限制慢连接。

请求带随机前缀操作编号。服务端短期保存回执，相同编号与内容重试时只返回当前状态，避免已执行的射击、道具和聊天重复执行；同编号不同内容拒绝。移动保留原回合与序号校验。服务重启仍不恢复进行中的房间，故本功能不等同于对局持久化。

长连接断开后自动重建，HTTP 保留兼容回退。原生 TLS 配置缓存复用，网页压缩由浏览器解码一次。回到前台会重新请求当前状态，长时间无包时重建连接。正常 304、命令响应与心跳视为链路活动，短暂超时不立即宣布掉线。持续无响应且连续失败后显示状态，15 秒后可提示重连，弹出通知至少间隔 30 秒。延迟仍受玩家网络、设备与线路影响。

## 验证

静音导出的 WebAssembly 使用真实触控事件和网络故障注入；Windows 使用非活动桌面与 Dummy 音频。覆盖延迟开局、连续点击、失败重试、短暂停顿、断线重连、中文聊天、再次开局及地图手势。服务端检查认证、来源、会话失效、跨玩家操作、重复操作回执、弹道缓存与重连全量恢复。HTTP 回退专项检查 304 清除失败记录及超时期间画面线程持续运行。

未进行实体手机弱网或输入法全覆盖测试，不保证所有网络没有延迟。性能优化没有降低画质或删减爆炸效果。结果见 validation/network-0.2.9.json。
