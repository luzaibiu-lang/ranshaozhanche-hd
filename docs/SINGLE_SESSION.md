# 同账号互斥登录

0.2.10 客户端与 Go 0.1.20 实现同账号单会话：Windows 与网页使用同一账号再次成功登录时，新会话取得控制，旧会话失效。错误密码不会撤销已有会话。

会话替换通过数据库事务完成，内存凭据缓存同步撤销，防止旧缓存重新接受已撤销凭据。数据库保存哈希与替换状态，不保存明文令牌。现存重复会话按到期时间与插入顺序保留最新项；替换记录重启后仍有效。

被替换端的 REST 命令与 WebSocket 均返回 session_replaced。客户端立即清除旧会话，返回登录页并显示“账号已在其他地方登录，请重新登录”；该清理不向服务器发送账号退出请求。旧端使用旧凭据关闭、退出或继续发命令，也不能使新端离房。账号原房间和席位由新登录继续使用。

正常密码预填保留，但登录必须手动提交。浏览器端不得因收到会话替换通知而自动登录抢回控制。移动、动画、地图、武器与特效本次没有修改。

Go 测试覆盖历史数据升级、事务失败回滚、重启持久化、并发登录单一有效凭据、错误密码、旧 REST 与 WebSocket 拒绝及旧端退出不影响新端。导出后的 Windows 游戏在非活动桌面、Dummy 音频下实际登录，随后真实浏览器登录同账号，检查 Windows 回到登录页并关闭后浏览器仍保有原房间。桌面与手机网页还分别进行了相反方向的登录替换。

报告见 validation/single-session-0.2.10.json。手机网页使用 Chromium 触控模拟，未覆盖实体手机与所有输入法。
