# 项目状态与核对边界

公开基线：**0.1.10**。这是独立重建实现，功能回归与原程序逐帧等价分别记录。

## 平台

| 平台 | 状态 |
| --- | --- |
| Windows x64 | 当前实际验证的游戏与独立登录器平台 |
| Linux amd64 | Go 服务支持构建；Godot 图形客户端未作为发行平台验收 |
| Web、Android、iOS、macOS | 后续方向，暂无已验收的对应客户端 |

各端未来可以复用 Godot 游戏逻辑与 Go 服务协议，但输入、登录存储、资源加载、生命周期和更新均需单独适配。

## 0.1.10 已完成的专项验证

| 检查 | 结果 |
| --- | --- |
| Go 测试 | 916 项含子测试通过，静态分析通过 |
| 商城与非战斗流程 | 358 项通过，覆盖双击只购买一次、余额与背包同步 |
| 真实购买并使用补给 | 35 项通过，覆盖小／大／团队补给和回血数字 |
| 图形恢复反馈 | 77 项通过，覆盖浮字、去重和过期事件 |
| 输入与迟到回包 | 54 项通过 |
| 窗口与操作 | 146 项通过 |
| 双客户端与 AI | 两张地图分别完成 10／9 轮，共 998 次同版本状态比较一致，并验证结算、返回、再开局 |
| 关闭恢复 | 模拟离房回包延迟 5 秒，客户端约 1.2 秒退出 |

这些是版本基线的本地隔离验收结果，不等同于所有设备上的性能保证。公开仓库提供可启用的 CI 模板；启用后可在 Actions 查看重新执行的检查结果。

## 仍需核实

- 救护弹与致盲弹的原版精确作用半径缺少充分证据，当前保留 50 游戏像素。
- 所有高级武器的分裂时序、原版碰撞形状与每个可选弹窗，尚不能统一标为逐帧等价。
- 更广泛显卡、DPI、网络环境和其他平台需要持续实测。
- 图形素材以既有资源为基底；宽屏与高分辨率绘制不等于所有位图均已重新绘制为高清素材。

## 开发顺序

1. 先补充现有玩法的复现用例、原版证据与多人稳定性回归。
2. 再逐项核对高级武器时序、资源透明通道和交互细节。
3. 在不改变游戏身份的前提下完善显示与动画。
4. 为 Web 和移动端逐步接入平台输入、生命周期和存储。

以上为开发方向，未完成内容不作为交付承诺。
