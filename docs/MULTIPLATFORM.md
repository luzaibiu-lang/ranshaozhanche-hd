# 0.2.0 多端与更新

桌面 Web 与 Windows 版本由同一个 Godot 4.5.1 项目导出，共用场景、原版资源、战斗表现和 Go 联机协议。账号、角色、背包、房间、聊天、地图与战斗状态由同一个高清版服务保存。经典版仍为独立系统。

## 启动与登录

Windows 双击游戏入口后先检查增量更新，校验并替换有变化的文件，再启动游戏内的注册和登录界面。没有变化时不重复下载。原生凭据使用 Windows DPAPI 保存于用户目录，发行包不携带账号资料。

0.1.17 的旧入口首次迁移仍需要完成一次旧登录；下一次启动采用新流程。新发布的 0.2.0 ZIP 直接使用新流程。无需重新发整个客户端给已安装的玩家。

浏览器通过官网的“网页版立即开玩”启动游戏；画布占满页面，游戏区域禁用右键菜单与方向键滚动。账号密码只用于提交登录请求，浏览器仅保存会话令牌。未勾选记住时令牌只保留在当前标签会话；勾选后可在重新打开时恢复。退出账号会撤销会话并清除浏览器中的令牌。

## 资源与服务

Web 使用单线程 WebAssembly 与 WebGL 2，无需 SharedArrayBuffer。资源采用内容哈希目录；入口 HTML 每次重新验证，哈希资源允许长期缓存。没有安装 Service Worker，避免旧壳长期覆盖新入口。发布保留旧资源目录，已打开的页面可继续运行。

首次压缩传输约 131 MiB。资源下载增加静态带宽与磁盘使用；战斗仍由玩家设备渲染，并非服务器逐帧串流画面。每位玩家的联机 API 开销与 Windows 同类。资源变化时浏览器会下载新的 Web 资源包；Windows 则继续按文件增量更新，两种发布机制不应混为一谈。

浏览器 API 由 HTTPS 网站同源代理至现有高清版服务，不要求玩家安装私有证书，不改经典版监听和数据库。本次客户端版本为 0.2.0；兼容的 Go 服务保持 0.1.17，版本号分别代表客户端和服务端构建。

## 验收边界

2026-11-27 使用实际导出的 Web 与打包后的 Windows `Game.exe` 连续两次在本机独立 Go 测试服验收。双方能进入同一房间、同步房主切图、互相显示战斗聊天、分别发射武器。连续两轮、六个行动位的地图、风、战车、血量、SP 与地形状态相符。退出测试对手触发结算后，双方使用界面按钮回房，切图并进入第二局；浏览器无未处理异常，Windows 正常退出。

Windows 更新器另验证了完整文件启动、单文件修复、更新器自升级、重复启动、旧版本首次迁移、下一次启动和旧版加密凭据兼容。静态页面测试覆盖官网三个入口、390 像素宽度、资源加载失败后的重试、游戏区域右键与键盘行为。所有桌面运行在非活动桌面，浏览器无头且静音。

验收不代表已经适配所有浏览器、显卡、输入法和设备。Android、iOS 原生包尚未交付；触控布局、虚拟键盘、安全凭据、移动端生命周期、商店签名及设备性能仍须分别实现和验收。当前统一项目与服务协议可作为后续端口的基础。

公网验收随后通过：官网三个入口均为 HTTP 200；实际桌面 Edge 完成游戏内注册、频道选择、进入大厅、退出和重新登录。窗口变化时画布跟随，游戏区域不弹出右键菜单，未捕获到 JavaScript 异常。WASM、PCK、JS 的 MIME、gzip 和内容哈希目录缓存头均经 HTTPS 验证。
